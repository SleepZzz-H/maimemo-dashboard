# 其他背单词软件能不能接进来

调研时间：2026-11-25。结论先说：**能"真的接数据"的只有三家**（墨墨、WaniKani、Anki），
其余要么没有公开接口，要么接口早就不对外了 —— 但**它们几乎都能导出词表**，所以真正通用的是"导入词表"这一条路。

## 一、逐个结论

| 软件 | 官方 API | 浏览器能直连 | 能拿到什么 | 工作量 | 判断 |
|---|---|---|---|---|---|
| **墨墨背单词** | 有（`open.maimemo.com`，Token） | 不能（带 Origin 就 403，需边缘函数中转） | 复习次数、最近一次回答、顽固标记、下次复习日期 | 已完成 | 已接 |
| **WaniKani**（日语） | 有（v2，Token） | **能**（`access-control-allow-origin: *`） | 每次复习的对错计数、SRS 阶段、下次可用时间、释义 | 1–2 天 | **最值得接** |
| **Anki** | 无云端 API，但有三条路 | 不能（本地服务） | 卡片、调度、复习历史（revlog） | 1 天（CSV）/ 3 天（插件） | **值得做导出** |
| Quizlet | 不再对新开发者开放（文档站已加验证码拦截） | — | 只能导出词集 | 半天 | 只做导入 |
| 扇贝 | 曾有开放平台，现 `open.shanbay.com` 打不开 | — | — | — | 只做导入 |
| 百词斩 / 不背单词 / 知米 / 拓词 | 无 | — | 无导出或仅 App 内 | — | 只做导入（手输） |
| 欧路词典 | 无 | — | 生词本可导出 txt | 半天 | 只做导入 |
| 有道词典 | 无官方免费 API（网页 `jsonapi` 是非官方，我们已在用） | 无 CORS | 释义 | — | 只当词典用 |
| Memrise / Duolingo / LingQ / Clozemaster | 无（Duolingo 只有社区逆向接口） | — | — | — | 不建议 |

## 二、为什么"有没有 API"不是唯一标准

这个看板/测验的核心是**"哪些词最容易忘"**，那需要知道**每次回答的结果**，而不是"这个词现在标记成什么"。

各家给的粒度完全不同：

- **墨墨**：只给 `study_count`（复习了几次）+ `last_response`（最近一次的判断）+ `sticky`。
  没有逐次历史 → 我们只能靠每天快照做差分补出来。这是现在最麻烦的地方。
- **WaniKani**：`review_statistics` 直接给 `meaning_incorrect` / `reading_incorrect` 累计次数，
  `reviews` 端点还给每一条复习记录（何时、答错几次、SRS 从几阶到几阶）。
  **这是主流服务里唯一天然提供"逐次错误"的**，接进来能直接算难度，不用快照。
- **Anki**：本地库里有 `revlog` 表（每次回答的评分 1–4、间隔、耗时）。
  AnkiConnect 插件能查（`getReviewsOfCards`），但导出 CSV 默认**不含** revlog。

所以：接 WaniKani 能拿到比墨墨更干净的数据；接 Anki 要么走插件（本地、重），要么只能拿到"词 + 释义"。

## 三、三条接入路线

### A. 官方 API（只有墨墨、WaniKani 走得通）

- 墨墨：Token → 边缘函数中转（已完成）。
- WaniKani：Token 放浏览器就能直接调，`Authorization: Bearer <token>` + `Wanikani-Revision: 20170710`。
  限流 60 次/分钟，返回 `RateLimit-Remaining` 头。分页 500/页，支持 `updated_after` 增量拉。
  - `GET /v2/assignments` → 每个词/汉字的 SRS 阶段、下次可用时间
  - `GET /v2/review_statistics` → 正确/错误累计
  - `GET /v2/subjects` → 拼写、读音、英文释义（这是 WaniKani 自己的内容，有版权限制）
  - 注意品牌的硬规定：**产品名不能含 "WaniKani"**，介绍必须写 "unofficial / 第三方"，
    不能抄它的配色和界面。违反会被要求下架。

### B. 导入导出（覆盖面最广，也最不容易坏）

几乎所有软件都能导出成文本，只要支持"粘贴或上传词表"，就等于一次性接入了全部：

| 来源 | 操作路径 | 导出的样子 |
|---|---|---|
| Anki | 浏览 → 全选 → 导出 → 「笔记（纯文本）」 | `单词<TAB>释义<TAB>标签` |
| Quizlet | 词集页 → ⋯ → 导出 → 制表符 | `单词<TAB>释义` |
| 欧路词典 | 生词本 → 导出 | `单词 释义` |
| 墨墨 | 云词本可复制 | 一行一词 |
| 百词斩等 | 没有导出 | 只能手输/截图 |

建议的导入格式就一种：**一行一个词，`单词 <TAB 或 逗号> 释义`，释义可省略**（省略就走有道自动补）。
解析几十行代码，之后所有平台的用户都能用。

### C. 非官方接口（不建议）

有道 `dict.youdao.com/jsonapi`（我们已经在用它取释义）、Duolingo 的社区逆向接口等：
随时可能改、可能封 IP、可能有 ToS 问题。只适合"取个释义"这种丢了也能降级的事，
不适合当数据来源。

## 四、建议的落地顺序

1. **通用词表导入**（1 天，收益最大）：粘贴/上传 → 解析 → 生成题库。
   一次性覆盖 Anki、Quizlet、欧路、百词斩…… 而且不依赖任何第三方存活。
2. **WaniKani 绑定**（1–2 天）：和墨墨绑定并列成第二个「数据源」，Token 存本地，
   直接浏览器调（不需要中转函数）。能拿到真正的错误次数，难度分更准。
   但要限定是日语内容，UI 上得说清楚。
3. **Anki 导出解析**（0.5 天）：用户从 Anki 导出纯文本粘进来即可，
   挂在第 1 条的导入功能下面，只需要多认一种格式（带标签列）。
4. 其余（Quizlet/扇贝/百词斩/欧路）：**不写专门适配**，靠第 1 条覆盖。

## 五、风险

- **接口存废**：墨墨的开放平台本身也是"新东西"（带 Origin 就 403 这种设计说明没打算给浏览器用）；
  WaniKani 的 v2 稳定但要遵守品牌规则。
- **内容版权**：WaniKani 的释义/助记是付费内容，只能用于个人学习展示，不能二次分发；
  Anki 牌组同理（很多牌组本身是侵权转的）。
- **数据准确性**：导入的词表没有历史，只能按"复习次数"估难度，和墨墨快照那套不是一个精度，
  UI 上要分开说明，不要混着排名。

## 六、怎么拿到「容易忘」的数据（按可得性排序）

要算"最容易忘"，需要的是**每次回答的结果**，不是词表。各家给的东西差得很远：

### 1. WaniKani：能拿到逐条，且浏览器直连

| 端点 | 拿到什么 |
|---|---|
| `GET /v2/review_statistics` | 每个词的累计 `meaning_correct` / `meaning_incorrect` / `reading_correct` / `reading_incorrect` |
| `GET /v2/reviews` | 每一条复习事件：何时、`starting_srs_stage` → `ending_srs_stage`、答错几次 |
| `GET /v2/assignments` | 当前 SRS 阶段、下次可用时间；`burned_at` 表示已烧（永不复习） |

难度可以两种方式算：

- 错误率 = `incorrect / (correct + incorrect)`
- SRS 降级次数：`ending_srs_stage < starting_srs_stage` 的那次就是答错了（这个更贴近"忘了"）

只读、Token 放浏览器就行、60 次/分钟、分页 500。

### 2. Anki：能拿到逐条，但只能在本机

Anki 的 `collection.anki2` 就是 SQLite，`revlog` 表存着每一次回答：

```
revlog(id, cid, usn, ease, ivl, lastIvl, factor, time, type)
```

- `ease`：1=Again 2=Hard 3=Good 4=Easy（1 就是"忘了"）
- `type`：0=学习 1=复习 2=重学 3=筛选 4=手动 5=重新排期
- `time`：这次答题花了多少毫秒

一条 SQL 就能排出来：

```sql
SELECT n.flds,
       COUNT(*) AS reviews,
       SUM(r.ease = 1) AS forgot,
       ROUND(1.0 * SUM(r.ease = 1) / COUNT(*), 2) AS forget_rate
FROM revlog r
JOIN cards c ON c.id = r.cid
JOIN notes n ON n.id = c.nid
GROUP BY n.id
HAVING reviews >= 3
ORDER BY forget_rate DESC, forgot DESC
LIMIT 50;
```

注意三点：

- Anki **必须关掉**再读，或者先复制一份库文件（它 WAL 锁着）；
- 新版库文件名可能是 `collection.anki21` / `.anki21b`，先看目录；
- 导出的"笔记纯文本"**不含 revlog**，所以想算错误率只能读库或用插件。

插件路线：AnkiConnect（addon id 2055492159）开在 `127.0.0.1:8765`，有 `getReviewsOfCards`、
`getCardInfo`、`findCards "prop:ivl<21"`。好处是 Anki 不用关；坏处是**只在本机**，网页版碰不到它。

### 3. 墨墨：只有聚合值，得自己攒

`study_count` + `last_response` + `sticky`，没有逐次历史 —— 我们现在的每日快照差分就是补这个。
局限：一天复习好几轮，只能看到最后一轮的结论。

### 4. 没有开放接口的那些（百词斩 / 不背单词 / 扇贝 / 知米 / 沪江 / 乐词）

按可行性从高到低：

| 办法 | 能拿到 | 门槛 | 风险 |
|---|---|---|---|
| **官方导出** | 一般只有词表/生词本，**没有错误历史** | 无 | 无 |
| **个人信息查阅复制请求** | 有可能拿到导出包（含学习记录） | 要发工单、等几天 | 《个人信息保护法》第 45 条有依据，但多数 App 会拖或只给粗略 CSV |
| **安卓无障碍 / UI 自动化**（Auto.js、Appium、`adb shell uiautomator dump`） | 你屏幕上能看到的一切：题目、你的选择、对错 | 一台安卓机 + 装工具，**不用 root** | 只适合自己设备、自己账号；速度慢；App 改版就要修 |
| **抓包**（mitmproxy/Charles + 装证书） | 接口里的原始字段，最全 | 安卓 7+ 默认不信用户证书，要 root 或改包；常有证书固定 | **违反用户协议**，App 一升级就断，不建议 |
| **截图 OCR** | 错题页上的词 | 简单，但要人工核对 | 量大了很痛苦 |

现实结论：这些 App 里"错题本/遗忘曲线"通常是**只给看不给导**的功能。想让数据出来，
要么走工单要导出，要么在自己设备上自动化"边背边记"。

### 5. 最可靠的一条：把本站测验当采集器

不管词从哪来（墨墨、Anki、Quizlet、手输），**在本站做一遍题**，对错就是我们自己的数据：

- 每题都有记录：对/错、用时、日期；
- 精度比任何聚合值都高（能区分"想了 20 秒才蒙对"和"秒答"）；
- 不依赖别人的接口是否还活着。

如果目标是"统一管理所有平台的易忘词"，这条路才是终局：别人的数据只用来**导词**，
遗忘判断交给自己的答题记录。想更快攒数据，可以一天多刷几组（每 50 词一组，题库够大就不重复）。
